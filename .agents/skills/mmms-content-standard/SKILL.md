# MMMS Content Standard

版本：0.1（草案）

对 `content/` 中的文章执行本规范。把事实准确和证据可追溯放在文风之前。需要改善表达和零基础可读性时，同时遵守 `editor-mouyase`；两者冲突时，以本规范的事实、日期、引用和链接规则为准。

## 编写流程

按以下顺序处理文章：

1. 判断文章属于概念类还是教程类。
2. 列出文章中的事实、版本信息和关键判断。
3. 为这些内容查找可靠来源，不使用记忆补全。
4. 写入 Frontmatter，并判断内容是否具有强时效性。
5. 按文章类型组织正文。
6. 给正文中的概念词添加内部链接。
7. 在文末整理资料来源。
8. 按发布检查表验收。

资料不足时停止补写。明确列出“需要查证”的内容，不编造来源、日期、版本、测试结果或原文。

## 文章分类

每篇文章只选择一种主要类型。无法明确分类时，先拆分文章。

### 概念类

概念类文章回答“这是什么”“为什么会这样”“它和相近概念有什么区别”。

概念类文章应包含：

1. 一句话定义；
2. 最少必要的背景；
3. 一个具体例子；
4. 与相近概念的区别；
5. 适用范围和例外；
6. 资料来源。

概念类文章可以链接其他概念类文章。不要直接链接教程类文章，也不要手工维护“相关教程”列表。

项目已经启用双向链接。教程引用某个概念后，该教程会出现在概念文章的反向链接区域。使用反向链接列出“哪些文章使用了这个概念”。

### 教程类

教程类文章回答“我要完成什么”“应该在哪里操作”“操作成功后会看到什么”。

教程类文章应包含：

1. 完成后的结果；
2. 适用设备、系统、软件和版本；
3. 准备条件；
4. 按顺序排列的操作步骤；
5. 每个关键步骤的预期结果；
6. 常见失败和恢复办法；
7. 验证最终结果的方法；
8. 风险、费用和数据影响；
9. 资料来源。

教程中出现必要概念时，链接对应的概念文章，不在教程里重复写一篇完整的概念说明。

0.1 版暂不规定教程文章之间的链接方式。不要自行增加限制。

## Frontmatter

所有文章至少使用以下字段：

```yaml
---
title: 文章标题
description: 一句话说明文章解决的问题
contentType: concept
created: 2026-07-25
modified: 2026-07-25
timeliness: stable
draft: true
---
```

字段规则：

- `contentType` 只使用 `concept` 或 `tutorial`。
- `created` 记录文件首次建立的日期，之后不要修改。
- `modified` 记录最近一次正文、事实、结构、步骤或来源发生变化的日期。只调整空格或格式时不必更新。
- `timeliness` 只使用 `stable` 或 `time-sensitive`。
- `draft` 在文章通过发布检查前保持为 `true`。
- 日期统一使用 `YYYY-MM-DD`，不要使用“今天”“最近”等相对时间。

不知道原始日期时，不要猜测。使用能够确认的日期，并在编辑说明中记录日期含义。

## 时效性

以下内容通常属于强时效性内容：

- 软件界面、功能、兼容性和安装方式；
- 操作系统、软件或硬件版本；
- 价格、套餐、会员权益和购买建议；
- 平台规则、服务范围和账号政策；
- 法律、监管、安全风险和漏洞信息；
- 下载地址、商店状态和在线服务可用性。

强时效性文章必须增加：

```yaml
timeliness: time-sensitive
lastVerified: 2026-07-25
appliesTo:
  - Windows 11 24H2
  - 中国大陆
```

同时在正文开头显示时效说明：

```markdown
> [!warning] 时效说明
> 本文最后核验于 2026-07-25，适用于 Windows 11 24H2 和中国大陆地区。软件界面、价格或平台规则变化后，部分步骤可能失效。
```

执行以下规则：

- `lastVerified` 表示编辑者重新核对了全文中的时效性事实，不能因为只检查了一处内容就更新。
- `appliesTo` 写明系统、软件版本、设备、地区或服务范围，只保留与文章有关的项目。
- 修改步骤但没有重新核验其他时效性信息时，只更新 `modified`，不要更新 `lastVerified`。
- 无法确认内容目前仍有效时，将文章设为草稿，并标出需要重新核验的内容。

## 事实与资料

### 不脑补

把内容分为以下四类：

- **事实**：可以由原始资料、官方文档或可重复测试验证。
- **测试结果**：编辑者在明确环境中实际观察到的结果。
- **建议**：根据目标、成本和风险提出的选择。
- **未确认判断**：证据不足，不能作为事实发布。

不得把测试结果扩大为所有设备、所有版本或所有用户都会出现的结果。记录测试日期、设备、系统、软件版本和关键条件。

AI 回答、搜索结果摘要、转载中的无来源结论和无法复现的传言不能作为资料来源。

### 来源优先级

按以下顺序选择资料：

1. 官方文档、标准、规范、发布说明、源代码仓库和原始数据；
2. 当事人或机构发布的一手材料；
3. 写明环境、步骤和结果的可重复测试；
4. 有编辑责任和署名的专业二手资料。

来源之间冲突时，不要静默选择其中一个。说明各自的日期、版本和适用范围，或者将结论标记为需要查证。

### 引用原文

需要依靠原文措辞证明结论时，直接摘录支撑该结论所需的原文。不要把改写内容放进引号，也不要整篇搬运来源。

使用以下格式：

```markdown
> 原文内容。
>
> —— 作者或机构，《资料标题》，发布日期或文档版本[^1]
```

引用外文时，先保留原文，再另起一段提供中文翻译，并标记“编者译”。不要只留下翻译后再称其为原文。

删去原文中间内容时使用省略号，不得改变原意。引用前后说明这段原文具体支持哪个判断。

### 文末资料来源

文章底部使用 `## 资料来源`。正文中的具体数字、版本、兼容性、政策、安全结论和直接引文使用脚注指向这里。

```markdown
## 资料来源

[^1]: 作者或机构，《资料标题》，文档版本或发布日期，更新日期，访问日期：2026-07-25。原始页面链接。
```

不要只贴一个网址。每条资料尽量记录：

- 作者或发布机构；
- 完整标题；
- 发布日期或文档版本；
- 页面标明的更新日期；
- 本次访问日期；
- 原始页面地址；
- 标准编号、版本号或公开存档地址（如果存在）。

网址只是访问入口，不是完整的来源记录。对于决定性且容易变化的资料，在正文中保留必要原文，并记录版本和日期，使页面失效后仍能判断引用了什么。

发布前打开每个来源，确认链接可访问、内容与引用一致，并确认没有把旧版本资料当作当前事实。

## 概念链接

概念词是读者必须理解，才能继续阅读当前文章的技术名词或基础知识。

执行以下规则：

1. 概念词在正文第一次实质出现时，链接对应的概念文章。
2. 使用 Quartz Wikilink：`[[概念文章]]`。
3. 显示文字与文件名不同时，使用 `[[概念文章|正文中的词语]]`。
4. 同一小节内重复出现的概念词不重复添加链接。
5. 不在标题中堆放概念链接。
6. 不为了增加链接数量，把普通词语包装成概念。
7. 链接目标必须解释该概念，不能只是在正文中碰巧提到它。

教程文章必须链接它依赖的概念文章。概念文章可以链接前置概念和相近概念，但不能主动链接教程文章。

概念文章尚不存在时，将其列为内容缺口。发布当前文章前，选择以下一种处理方式：

- 先创建并完成概念文章，再添加链接；
- 在当前文章中给出足够的短解释，并确认该词不需要独立概念文章。

不要发布空白概念页，也不要为了满足链接规则编造定义。

## 输出要求

### 编写文章

直接输出符合本规范的 Frontmatter 和正文。资料不足时，先输出能够确认的部分，再单独列出“需要查证”和“缺少的概念文章”。

### 审查文章

按以下顺序报告：

```markdown
## 发布结论

## 必须修改

## 需要查证

## 缺少的概念链接

## 建议修改
```

只输出有内容的章节。事实错误、缺少关键来源、时效信息不完整、链接方向错误和关键概念缺页都属于发布阻断问题。

## 发布检查

发布前逐项确认：

- [ ] `contentType` 正确，文章没有混合两个主要类型；
- [ ] `created` 和 `modified` 使用准确的绝对日期；
- [ ] 强时效性文章填写 `lastVerified`、`appliesTo`，并显示时效说明；
- [ ] 关键事实可以追溯到可靠资料或明确测试；
- [ ] 没有把 AI 回答、搜索摘要或记忆当作来源；
- [ ] 直接引文与原文一致，删节没有改变原意；
- [ ] 文末资料来源不是裸网址，包含标题、机构、日期或版本；
- [ ] 教程链接所需概念；
- [ ] 概念文章没有主动链接教程；
- [ ] 链接目标存在，并真正解释对应概念；
- [ ] 来源链接仍可访问，引用内容仍能复核；
- [ ] 所有发布阻断问题已经解决，再把 `draft` 改为 `false`。

## 0.1 版边界

本版本只规定文章分类、日期与时效、事实资料、原文引用和概念链接。目录结构、文件命名、标签体系、教程之间的链接、图片规范、截图更新、文章废弃流程和自动检查工具留到后续版本讨论。
